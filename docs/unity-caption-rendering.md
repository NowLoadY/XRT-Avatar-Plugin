# Unity caption renderer

`presentation/unity/` owns the SDK-independent caption mesh, SDF shader, font
resources and editor resource loader. Adapters own transport parameters,
receiver construction, installation and object attachment. A game can use this
renderer without adopting VRChat's transport or Animator setup.

`tools/sync_unity_presentation.py` copies shared rendering assets and
the shared helpers in `authoring/unity/` into the VRChat and ChilloutVR packages.
Edit the shared source, then run that script; package copies retain the same
asset GUIDs. The authoring helper owns preset tiles, material defaults and
preview text, object selection and removal of owned display components. It renders
the caption mesh through `PreviewRenderUtility`.

VRChat fills the material through its Animator buffer. ChilloutVR uses an Avatar
Lua receiver and two packed integer words. Both consume the connector SDK's
128-slot BMP layout and reuse the host's pacing and cancellation. A present
header/footer occupies the first/last row. The SDK fits recent messages into the
remaining rows and updates only changed chunks, preserving other regions. Each
avatar uses one source layout and bus; multiple text objects mirror that source
with independent materials and transforms. Generated text can be parented to the
user's prop or animation hierarchy. The shared removal helper keeps objects with
user-added components, children or replacement meshes/materials.

## Surface and text

`XrtAvatarPlugin.Presentation.CaptionAssets.CreateMesh()` creates one merged mesh
with 128 glyph quads and one background quad: 516 vertices, one renderer and one
material. UV1 identifies glyph slots; retain it when adapting the mesh.
`CreateMaterial()` binds the bundled textures to `XRT/Avatar Caption`.
The fixed byte-property declarations and bounded selector in
`XrtCaptionBytes.hlsl` are generated by `tools/build_caption_font.py --bindings`;
rendering and layout remain in `XrtAvatarCaption.shader`.

The shader reads `_Byte0` through `_Byte255`. Each high/low pair encodes one BMP
Unicode character. Zero clears a slot. `_Columns` selects the source's 8–32 slots
per row.
Default horizontal dimensions are 0.64 × 0.10 m with 32 columns; portrait is
0.24 × 0.60 m with 8 columns. Both use `_CellAspect = 1.25`.

The shader uses the transform's X/Y dimensions to wrap proportional text and
clip overflow inside the surface, showing only complete lines. Z provides the
scale reference: resizing X/Y changes available space; uniform XYZ scaling
enlarges everything together.
`_FontSize` controls glyph size and `_CellAspect` controls line spacing.
Latin words stay together when they fit; longer words and CJK wrap by character.
Source row breaks remain intact, including header/footer boundaries. Increasing
surface width cannot recover text already omitted by the 128-slot source layout.
Layout scans at most 128 slots per vertex; fragments sample one SDF cell.
The renderer does not parse rich text. Normalize input to NFC before layout.

Horizontal and Portrait default to transparent lettering. Board defaults to a
light opaque background with a rounded slate border. Transparent presets use white
text with a dark SDF outline. Appearance exposes text size, text/outline/background/
border colors (including alpha) and widths. Layout groups line spacing, padding,
corner radius and hiding empty captions. Padding, border width and corner radius
use fractions of the surface height. An all-zero buffer hides the whole
surface by default. No runtime script, TMP component, per-glyph GameObject or
per-glyph material is required.

Text and outline share one atlas sample and draw pass. Editor previews reuse their
render texture until the text, material, surface dimensions or preview size changes.

## Font resources

The bundled font is derived from **Noto Sans CJK SC Regular 2.004**, copyright
2014–2021 Adobe, under the SIL Open Font License 1.1. The copyright notice and
license ship in `Runtime/Caption/OFL.txt`.

The 14,087-glyph subset combines supported Latin, Greek and Cyrillic characters
with GB2312, Shift_JIS and EUC-KR repertoires. The exact codepoint-to-cell table,
source URL and source SHA-256 are in `XrtCaptionFont.json`. CJK shapes follow the
Simplified Chinese font face. Missing characters use a square replacement glyph;
this is not an emoji or complex-script shaping engine.

| Resource | Imported format | Base GPU allocation |
|---|---|---:|
| 4096 × 4096 distance atlas | R8, bilinear, linear data | 16 MiB |
| 256 × 256 Unicode lookup | RGBA32, point, linear data | 256 KiB |

There are no mipmaps or CPU-readable copies. The two PNG files total about
5.2 MiB on disk. Meshes and materials share these font textures. The importer
sets these formats explicitly so platform defaults do not compress glyph
addresses or expand the atlas to a color texture.

## Regeneration

The build tool uses Python with Pillow, NumPy, SciPy and fontTools. Download the
pinned OTF linked by the manifest into an ignored local directory; the tool
rejects a font whose SHA-256 differs. The source font is not included in releases.

```sh
python3 tools/build_caption_font.py \
  --font scratch/caption-font/NotoSansCJKsc-Regular.otf \
  --preview scratch/caption-font/preview.png
python3 tools/sync_unity_presentation.py
```

The atlas uses four-times supersampled glyph masks and a four-pixel signed
distance spread, then stores 32-pixel cells. The preview samples the generated
atlas and the same proportional advances; it is a font proof, not a Unity or
game screenshot. Asset generation and lookup consistency can be checked without
Unity. Shader compilation, Animator binding and remote-player rendering still
require the Unity and game acceptance workflow.
